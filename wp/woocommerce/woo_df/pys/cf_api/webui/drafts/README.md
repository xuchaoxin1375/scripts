# WebUI 交互草稿（静态）

三版可点击的设计草稿，用于选择 DNS 控制台的导航与编辑方式。全部是 mock 数据，
不调用 `/api/v1`，不写 Cloudflare，也不影响现有 `webui/v2/`。

**已选定草稿 B**：全局 Rail + 顶栏资源切换 + 弹窗编辑 + 右侧批量抽屉，已在
`webui/v2/` 落地；A/C 保留供回退。

打开入口：[index.html](index.html)。

## 怎么查看

- 直接双击 `index.html`，或在本目录执行 `python -m http.server 8610` 后访问
  `http://127.0.0.1:8610/`。
- 每页底部有 **Draft controls**，可切换 Normal / Loading / Empty / Error 状态。
- 右上角可切换浅色 / 深色；窄屏可打开左侧导航抽屉。

## 三版定位

| 草稿 | 导航 | 单条编辑 | 批量 / 任务 | 适用 |
|---|---|---|---|---|
| A | Cloudflare 式全局侧栏 + 顶部资源切换 | 弹窗 | 弹窗或独立页 | 最接近 Cloudflare，单条编辑优先 |
| B | 全局侧栏（默认 Rail）+ 顶部资源切换 | 弹窗 | 右侧抽屉 | 单条编辑与批量预览都要保留，推荐 |
| C | 当前账号/域名侧栏 | 弹窗 | 右侧 Inspector | 最小改动，保留现有操作习惯 |

**推荐 B**：它保留 Cloudflare 式全局导航与弹窗编辑，同时用右侧抽屉承载批量预览、
diff 和任务，不需要把高频批处理塞进弹窗。

## 建议试的操作

- 点击行末 `Edit`，修改内容后保存；检查弹窗 Esc、遮罩关闭和关闭后的焦点回归。
- 点击 `Add record`，空内容提交，检查字段错误与首错聚焦。
- 勾选 2–3 条记录：A 打开批量内容弹窗；B 打开右侧 batch drawer 并预览；C 看 Inspector 的选中计数。
- 删除一条记录：确认复选框未勾选时删除按钮不可用。
- 折叠/展开侧栏（A/B），或在 390px 下打开/关闭导航抽屉。
- 切换浅色/深色和 Normal / Loading / Empty / Error 状态。

## 草稿与正式施工的边界

草稿只用于确认布局、信息架构和交互方向，**不是实现目标**。草稿通常会省略或简化
skill 中的长期要求（状态模型、时序、键盘与触屏、点击稳定、验收覆盖）；正式施工
必须按对应 skill 补齐这些细节，不能因为草稿没画就省略。

本轮反例：草稿 B 只有顶栏折叠按钮和静态页脚，v2 按草稿落地时漏掉了 fable 外壳的
Rail 悬停/键盘临时展开、页脚收起/展开、Esc、`[` 快捷键和覆盖式槽宽不变；这些项在
v1 的 `TASKS.md` 已有记录，v2 重写时没有回查。

施工前先列 skill 对照清单，草稿未覆盖的条目默认纳入；验收按 skill 补测，只测草稿
画出的按钮不算完成。

## 边界

- 草稿标签暂用英文，便于与 Cloudflare 参考交互对照；选定方案进入实现时沿用现有中文文案。
- 草稿只验证信息架构、交互和视觉方向，不证明后端契约、真实任务结果或生产可用性。
- 草稿中的保存、删除、预览、执行都是本地模拟，不会发起网络请求。
- 已选定 B 并在 `webui/v2/` 落地；A/C 保留供回退。
