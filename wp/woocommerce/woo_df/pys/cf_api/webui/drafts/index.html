Choose the interaction model

Three clickable drafts for the DNS console. All data is mock data; no API is called and the existing v2 app is untouched. Try Add / Edit / Delete, select a few rows, collapse the sidebar, switch the theme, and resize the window to 390px.

The small Draft controls pill at the bottom of each page switches Normal / Loading / Empty / Error states. Open a draft in a new tab for the full viewport.
Draft A

Global sidebar + modal editing

The closest to the Cloudflare dashboard: global navigation on the left, resource switcher on top, and every single-record change in a focused modal.

  • Best for: fast navigation and single-record edits.
  • Gain: clear hierarchy; the table keeps its context.
  • Cost: batch preview and task detail need a modal or a separate page.
Open Draft A
Draft B

Global sidebar + modal + batch drawer

Recommended

Keeps the Cloudflare-style navigation and modal edit, while a right-side drawer holds batch selection, preview diff and execution. The hybrid preserves the current tool's strongest workflow.

  • Best for: teams that do both single edits and batch DNS changes.
  • Gain: fast single edits without losing preview/job context.
  • Cost: one more layer of state than Draft A; focus handling must stay explicit.
Open Draft B
Draft C

Current workspace + modal editing

The smallest change: keep the account/zone navigator and the right inspector, but move single-record editing into the same modal as Draft A/B.

  • Best for: minimizing change and preserving current muscle memory.
  • Gain: no routing rewrite; inspector still handles batch and tasks.
  • Cost: does not deliver the global Cloudflare-style navigation.
