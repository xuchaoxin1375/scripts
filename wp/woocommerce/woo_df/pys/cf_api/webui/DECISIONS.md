# 决策记录（WebUI 单一前端重建）

- 日期：2026-10-07；决定：FastAPI + 单文件原生前端（现为 `webui/v1/dist/index.html`），后端 `/api/v1` 为主 + `/api` 兼容。
- 为什么：仅自己本机用，浏览器打开最快；无 Node 重依赖，`npm run build` 仅复制；复用引擎 `SPEED_PRESETS`/校验/失败清单，不由前端算。
- 放弃了：Vite+React（交互更强但需工具链）、Tauri 桌面壳（要窗口托盘才需要）、双前端（历史主败因）。
- 假设：Python 3.9+ 且愿装 fastapi/uvicorn；契约沿用 WEBUI_LESSONS 第一节；无需对外监听。

## 最新 skill 落地（2026-10-08，复用口径：直觉层冻结，功能层自定义）

- 复用项：工具栏九层骨架（搜索＋筛选草稿应用＋显示＋导入＋导出＋新增 primary 最右）、计数条、复选列、三态排序与 `aria-sort`、代理与 TTL 与备注与详情与警告列、短名显示、列宽调节（热区＋键盘步长＋还原＋持久）与显示区重置、行内展开与新增卡共用同一表单同一校验、悬浮批量条与删除撤销、导入预检门、窄屏卡片。功能接线（列定义、字段、导航项、校验函数体）按本机运维业务重写，对接真实接口。
- 有意未做（非目标，配套元素不留半套）：
  - 配额上限数：无配额查询接口，计数条如实显示条数，不虚构上限。
  - 记录编辑草稿持久化：编辑仅实例内，符合表单规范；操作页新建类表单已持久化草稿。

## 2026-11-15 草稿与正式施工的边界

- 决定：设计草稿只用于确认布局、信息架构与交互方向，不作实现目标；正式实现按 `admin-console-design` 的完整状态模型与验收底线补齐。
- 为什么：`drafts/draft-b.html` 只有顶栏折叠按钮和静态页脚，v2 按草稿落地时漏掉 fable 外壳的 Rail 悬停/键盘临时展开、页脚收起/展开、Esc、`[` 快捷键与覆盖式槽宽不变；这些项在 v1 的 `TASKS.md` 已有记录，重写时没有回查。
- 后果：施工前列 skill 对照清单，草稿未覆盖的条目默认纳入；验收补测悬停/焦点 peek、Esc、页脚按钮、主内容几何不变与快捷键，只测草稿画出的按钮不算完成。
