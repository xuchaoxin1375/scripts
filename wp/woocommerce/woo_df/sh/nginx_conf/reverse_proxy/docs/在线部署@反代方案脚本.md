## 适用场景

本文说明反代方案脚本的在线部署：不预先克隆仓库，用 `bash <(curl -SfL <raw>)` 直接执行主分支上的最新脚本。适用于新服务器首次部署、临时排查与快速切换模式。

需要审查脚本内容、离线运行或改动代码时，改用本地仓库脚本，见 [scripts/README.md](../scripts/README.md)。在线与本地执行只是脚本来源不同，参数、产物与行为一致。

## 前置条件

- Linux 服务器，具备 root 权限（写 nginx 配置、重载服务需要）。
- 已安装 nginx 或 openresty；在线部署只拉取脚本与配置模板，不安装 nginx。
- 可访问 `raw.githubusercontent.com`；国内网络可改用 gitee 原始链接，或先配置代理。

## 通用约定

- **自动更新仓库**：`base.sh`、`multi.sh`、`tenants.sh` 默认调用 `update_repos.sh`，把仓库更新到 `$HOME/repos/scripts` 并建立 `~/sh`。`multi.sh`、`tenants.sh` 用 `--no-update-code` 跳过，`base.sh` 用 `-D` 跳过。
- **总是最新代码**：在线执行取的是主分支当前版本，不锁定提交；需要与线上环境版本一致时改用本地仓库脚本。
- **先审查再执行**：先下载到文件，查看后再执行，例如 `curl -SfL <raw> -o ~/base.sh && bash ~/base.sh --help`。
- **gitee 备用源**：把前缀 `https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/` 换成 `https://raw.giteeusercontent.com/xuchaoxin1375/scripts/raw/main/`。
- **`$0` 显示为 `/dev/fd/N`**：进程替换执行的脚本没有固定文件名，日志与错误前缀以此为准；需要固定脚本名或反复执行时，下载到文件更合适。
- **宝塔路径**：下文的 `/www/logs/` 按实际安装替换，宝塔面板的日志目录也可能是 `/www/wwwlogs/`。

## 各方案命令

### 单机 simple：所有域名转同一后端

```bash
# 标准 nginx 路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/base.sh) -i <upstream_ip>

# 宝塔路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/base.sh) -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -i <upstream_ip>
```

### 单机 hostmap：按 Host 分流到不同后端

```bash
# 标准 nginx 路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/base.sh) -G hostmap

# 宝塔路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/base.sh) -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -G hostmap
```

生成 `gateway.conf` 与 `gateway/maps/routes.map.conf`；映射表已存在时不会被覆盖，后续按 [不同反代模式下(hostmap)nginx目录结构参考.md](<不同反代模式下(hostmap)nginx目录结构参考.md>) 维护。

### 多出口 IP：反代服务器与后端一一对应

```bash
# 标准 nginx 路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/multi.sh) -m 'B1_IP->A1_IP' -m 'B2_IP->A2_IP'

# 宝塔路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/multi.sh) -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -m 'B1_IP->A1_IP' -m 'B2_IP->A2_IP'

# 预览：只输出生成的配置，不写文件、不 reload
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/multi.sh) --dev -m 'B1_IP->A1_IP'
```

### 多租户：每租户独立 listen IP 与路由表

```bash
# 标准 nginx 路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/tenants.sh) -t 'a=P_IP_A' -t 'b=P_IP_B'

# 宝塔路径
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/tenants.sh) -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -t 'a=P_IP_A' -t 'b=P_IP_B'
```

路由用 `-r '<id>:<host>-><backend>'` 追加，或用 `-R` 读取路由文件；预览加 `--dev`。默认保留已有租户的 `routes.map`。

### 巡检与清理

```bash
# 只检查现状，不删文件
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/clean.sh) --status

# 切换模式前：清理全部方案的 D 侧残留，默认保留 map 数据
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/clean.sh) --mode all --force
```

清理范围与副作用见 [clean@清理说明.md](clean@清理说明.md)。

### 端口与防火墙检查

```bash
# 只检查
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/check_ports.sh) --ports 80,443

# 未放行时尝试放行
bash <(curl -SfL https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts/check_ports.sh) --fix --ports 80,443
```

## 部署后验证

```bash
nginx -t
nginx -s reload

curl -sS http://127.0.0.1/__b_health                             # simple / multi
curl -sS -H 'Host: <domain>' http://127.0.0.1/__gateway_health   # hostmap
curl -sS -H 'Host: <domain>' http://<tenant_listen_ip>/__tenant_health   # tenants
```

健康检查地址由对应模板或脚本生成；多出口与多租户场景把地址换成实际 listen IP。

## 在线与本地执行

| 方式 | 适用场景 | 注意 |
| --- | --- | --- |
| 在线 | 新机首次部署、临时排查、快速切换 | 总是取主分支最新代码，依赖网络可达 |
| 本地 | 反复执行、审查脚本、离线环境 | 需先克隆并保持更新；`--dev` 只预览，不拉取仓库 |
