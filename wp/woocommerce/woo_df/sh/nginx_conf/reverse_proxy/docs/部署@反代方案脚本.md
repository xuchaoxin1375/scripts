## 部署流程

反代方案脚本的部署分两步：先准备仓库，再按方案执行对应脚本。首次部署与后续更新使用同一套脚本。

`base.sh`、`multi.sh`、`tenants.sh` 默认会调用 `update_repos.sh` 更新仓库；不想改动仓库时加 `--no-update-code`(`base.sh` 用 `-D` 调试模式)。

### 1. 准备仓库

```bash
git clone --depth 1 https://github.com/xuchaoxin1375/scripts.git ~/repos/scripts
ln -snfv ~/repos/scripts/wp/woocommerce/woo_df/sh ~/sh
```

`~/sh` 是脚本与配置模板的统一入口，部署脚本按该路径取模板。已有仓库时改用 `git -C ~/repos/scripts pull` 或 `bash ~/sh/update_repos.sh`；`~/sh` 已存在时先确认它指向本仓库。

### 2. 选择方案并执行

前置条件：Linux 服务器与 root 权限(写 nginx 配置、重载服务需要)；已安装 nginx 或 openresty，脚本不负责安装 nginx。

后文命令使用脚本目录变量；单独开新会话时先重新执行这一行：

```bash
scripts=~/sh/nginx_conf/reverse_proxy/scripts
```

宝塔环境的 `-l` 日志目录按实际安装调整，也可能为 `/www/wwwlogs/`。

#### 单机 simple：所有域名转同一后端

```bash
# 标准 nginx 路径
bash "$scripts/base.sh" -i <upstream_ip>

# 宝塔路径
bash "$scripts/base.sh" -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -i <upstream_ip>
```

#### 单机 hostmap：按 Host 分流到不同后端

```bash
# 标准 nginx 路径
bash "$scripts/base.sh" -G hostmap

# 宝塔路径
bash "$scripts/base.sh" -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -G hostmap
```

生成 `gateway.conf` 与 `gateway/maps/routes.map.conf`；映射表已存在时不会被覆盖，后续按 [不同反代模式下(hostmap)nginx目录结构参考.md](<不同反代模式下(hostmap)nginx目录结构参考.md>) 维护。

#### 多出口 IP：反代服务器与后端一一对应

```bash
# 标准 nginx 路径
bash "$scripts/multi.sh" -m 'B1_IP->A1_IP' -m 'B2_IP->A2_IP'

# 宝塔路径
bash "$scripts/multi.sh" -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -m 'B1_IP->A1_IP' -m 'B2_IP->A2_IP'

# 预览：只输出生成的配置，不写文件、不 reload
bash "$scripts/multi.sh" --dev -m 'B1_IP->A1_IP'
```

#### 多租户：每租户独立 listen IP 与路由表

```bash
# 标准 nginx 路径
bash "$scripts/tenants.sh" -t 'a=P_IP_A' -t 'b=P_IP_B'

# 宝塔路径
bash "$scripts/tenants.sh" -c /www/server/nginx/conf -d /www/server/panel/vhost/nginx -l /www/logs/ -t 'a=P_IP_A' -t 'b=P_IP_B'
```

路由用 `-r '<id>:<host>-><backend>'` 追加，或用 `-R` 读取路由文件；预览加 `--dev`。默认保留已有租户的 `routes.map`。

#### 巡检与清理

```bash
# 只检查现状，不删文件
bash "$scripts/clean.sh" --status

# 切换模式前：清理全部方案的 D 侧残留，默认保留 map 数据
bash "$scripts/clean.sh" --mode all --force
```

清理范围与副作用见 [clean@清理说明.md](clean@清理说明.md)。

#### 端口与防火墙检查

```bash
# 只检查
bash "$scripts/check_ports.sh" --ports 80,443

# 未放行时尝试放行
bash "$scripts/check_ports.sh" --fix --ports 80,443
```

## 部署后验证

```bash
nginx -t
nginx -s reload

curl -sS http://127.0.0.1/__b_health                             # simple / multi
curl -sS -H 'Host: <domain>' http://127.0.0.1/__gateway_health   # hostmap
curl -sS -H 'Host: <domain>' http://<tenant_listen_ip>/__tenant_health   # tenants
```

健康检查地址由对应模板或脚本生成；多出口与多租户场景把地址换成实际 listen IP。

## 更新与切换

- 更新仓库：`git -C ~/repos/scripts pull`；需要同时更新 shellrc、nginx 与 fail2ban 配置时用 `bash ~/sh/update_repos.sh`。
- 切换方案：先 `bash "$scripts/clean.sh" --status` 巡检，再用 `bash "$scripts/clean.sh" --mode all --force` 清掉 D 侧残留，最后执行新方案脚本。
- 固定当前检出：给 `base.sh` 加 `-D`，给 `multi.sh`、`tenants.sh` 加 `--no-update-code`。

## 在线执行(可选)

不准备克隆仓库时，把脚本地址换成 raw 前缀，参数与本地执行一致：

```bash
RAW='https://raw.githubusercontent.com/xuchaoxin1375/scripts/refs/heads/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts'
bash <(curl -SfL "$RAW/base.sh") -i <upstream_ip>
```

把 `base.sh` 换成 `multi.sh`、`tenants.sh`、`clean.sh`、`check_ports.sh` 即可；国内可把 `RAW` 换成 gitee 前缀 `https://raw.giteeusercontent.com/xuchaoxin1375/scripts/raw/main/wp/woocommerce/woo_df/sh/nginx_conf/reverse_proxy/scripts`。`base.sh`、`multi.sh`、`tenants.sh` 在线执行时仍会自动更新仓库。
