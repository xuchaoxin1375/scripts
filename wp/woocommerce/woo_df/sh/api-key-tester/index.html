快速上手（三步）

CORS 是什么？为什么 curl 能用、网页不行？

CORS（跨域资源共享）是浏览器的一项安全策略：网页只能读取"同源"（协议 + 域名 + 端口一致）服务器的响应；要跨域读取，服务商必须显式返回 CORS 授权响应头。

  • curl / Python / 后端代码：不受浏览器同源策略约束，天然可以访问任何 API —— 所以导出的 curl 能通
  • 网页版：请求其实已经发出去了，但如果服务商没返回 CORS 授权头，浏览器会把响应整包丢弃，表现为"请求被拦截（疑似 CORS）"
结论：curl 可用而网页不行，几乎一定是 CORS 拦截，与 Key 是否正确无关。本工具失败时会自动探测服务器可达性（OPTIONS 预检）并给出等价 curl，帮你快速确认。
CORS 的解决办法
  1. 用本工具自带的本地后端（推荐，一键解决）：终端执行 ~/api-key-tester/start.sh（停止用 stop，状态用 status）。页面会显示"测试通道"并默认使用服务器通道——由本地后端代发请求，行为与 curl 一致，不再受浏览器 CORS 限制
  2. 换用支持 CORS 的服务商：OpenAI / Anthropic / Google / Groq 等官方接口普遍支持浏览器跨域；部分第三方中转站不支持，挑选时可优先选择支持 CORS 的
  3. 用终端 / 后端调用：点"导出代码"得到 curl / Python / JS 代码，在命令行或服务器执行 —— 本工具测试用的请求与你导出的代码完全一致
  4. 本地起一个通用 CORS 转发代理（不开后端时可用，示例）： 
    # 例如用 npx 起代理（无需安装到项目，按提示选择即可）
npx local-cors-proxy --proxyUrl https://你的API域名 --port 8010
# 然后网页里把 API 地址填成：
http://localhost:8010/v1
    代理会把浏览器请求原样转发到目标 API，并自动补上 CORS 授权头
  5. 浏览器插件临时放行：如各类 CORS 浏览器扩展（仅建议本地调试使用，请勿在处理敏感数据时依赖插件）
常见问题
  • 401 / 403 / 404 / 429 分别代表什么？ 依次为：Key 无效或过期 / 无权访问该模型或渠道 / 地址或模型名不存在 / 请求过频或余额不足。每次测试报告都会给出对应中文解释
  • 支持哪些服务商？ OpenAI、Anthropic、Gemini 及所有 OpenAI 兼容中转站；鉴权方式自动适配（Bearer / x-api-key / URL 参数）
  • 我的 Key 安全吗？ Key 只存在你浏览器的 localStorage 中（本机），仅在点击体检时直连对应 API，无任何第三方服务器中转。可取消"记住 Key"并清空历史记录
  • 如何一次测试多个模型？ 模型框用英文逗号分隔多个模型名；或先体检获得模型列表，再从右侧下拉挑选
  • 导出代码与网页测试结果为什么一致？ 因为页面发送的请求就是导出代码中的那一条，只是多了浏览器的 CORS 检查
